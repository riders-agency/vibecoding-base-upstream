# Логотип сайта в SVG

## Коротко

Логотип бренда в интерфейсе сайта используется в SVG из проверенного векторного оригинала. Он сохраняет пропорции и четкость, имеет доступное название и корректно выглядит в мобильной версии, светлой и темной теме.

## Плохо

```html
<a href="/">
  <img src="/assets/logo-small.png" alt="">
</a>
```

## Хорошо

```html
<a href="/" aria-label="Бренд — главная">
  <img src="/assets/logo.svg" alt=""
       width="144" height="40">
</a>
```

## Почему

Векторный оригинал позволяет менять размер без пикселизации графических контуров. Расширение `.svg` само по себе этого не гарантирует: внутри может быть маленькая растровая картинка. Размеры, контраст и название ссылки важны не меньше формата файла.

## Когда применять

Для логотипа собственного бренда в шапке, подвале и других управляемых частях web-интерфейса. SVG обязателен в этой области по соглашению справочника; HTML и WCAG не требуют именно этот формат для каждого логотипа.

Favicon, иконки приложений, письма и внешние площадки проверяются по своим форматам. Если владелец чужого бренда предоставляет только утвержденный растровый знак или знак содержит необходимую фотографическую часть, запросите подходящий оригинал либо зафиксируйте обоснованное исключение. Переименование PNG в SVG и обертка с растровым изображением не считаются векторизацией. Наличие логотипа SVG не требует SVG-иконок у пунктов меню.

### Требования

- Используйте утвержденную векторную версию без изменения написания, пропорций и существенных деталей. При экспорте сохраняйте корректный `viewBox`, отсутствие обрезания и исходное соотношение сторон.
- Укажите размеры области отображения или соотношение сторон до загрузки. Масштабируйте без растяжения; компактный знак для телефона берите из утвержденного набора. В примере размеры условные и должны соответствовать реальному файлу.
- Для обычного статичного логотипа предпочтителен проверенный локальный файл через `<img src="…svg">`. Inline SVG допустим, когда это нужно для управления цветами или другой согласованной функции, но его разметка должна быть доверенной и проверенной.
- Удаляйте из исходника ненужные метаданные редактора, комментарии с внутренними данными и неиспользуемые объекты. Не допускайте скрипты, обработчики событий, ненужный `foreignObject` и внешние зависимости. Не вставляйте произвольный SVG из загрузки пользователя прямо в HTML.
- Ограничения SVG в режиме изображения не равны безопасности SVG-документа: при прямом открытии или в `<object>` возможности отличаются. Приемка файла и контроль способа встраивания нужны даже если вариант через `<img>` отображается правильно.
- Логотип-ссылка получает имя с брендом и назначением, например «Бренд — главная». В хорошем примере оно задано на ссылке, поэтому `alt` вложенного изображения пустой во избежание повторного имени. Если название передается через сам `<img>`, задайте соответствующий `alt` вместо дублирования двух описаний.
- Логотип без ссылки должен иметь осмысленное текстовое описание, если его смысл не продублирован рядом. У inline SVG обеспечьте эквивалентное доступное имя либо исключите графику из дерева доступности, когда имя уже передает родительская ссылка.
- Проверьте светлую и темную темы, высокий масштаб и малый размер: важные части не исчезают на фоне. Оптимизация не удаляет необходимые цвета, маски и пропорции. SVG не становится автоматически самым маленьким файлом — оцените фактический размер.
- URL отдает SVG с корректным типом `image/svg+xml`. После смены логотипа версия ресурса и правила кеширования обеспечивают загрузку обновления. При ошибке файла назначение ссылки остается понятным.

## Пример применения

У вымышленного бренда есть полный горизонтальный логотип и компактный знак. Оба сохранены как проверенные SVG. Шапка выбирает нужный вариант по доступному месту, а ссылка в обоих случаях называется «Бренд — главная». Favicon экспортируется отдельно согласно требованиям целевых платформ.

## Как проверить

- Проверьте исходник: настоящий SVG, корректный `viewBox`, отсутствие подмены маленьким растром, внутренних данных, активного содержимого и неожиданных внешних запросов.
- Откройте страницу в обеих темах, на телефоне и при увеличении: контуры четкие, логотип не растянут и не обрезан, место зарезервировано.
- Пройдите ссылку клавиатурой и скринридером: назначение понятно и не произносится дважды. Проверьте вариант без ссылки отдельно.
- Проверьте MIME, отказ загрузки и замену ресурса с прежним кешем. Старая картинка не должна оставаться единственным доступным вариантом после обновления.
