# Сохранение адресов при переносе сайта

## Коротко

Сохраните смысл каждого существующего адреса. Если адрес меняется, сопоставьте его с эквивалентом или зафиксируйте причину удаления.

## Плохо

```text
Адреса пересобраны из новых названий.
Все старые URL → главная.
Хлебные крошки ведут на старый сайт.
Sitemap содержит технический стенд.
```

## Хорошо

```text
/catalog/item-a → тот же товар.
Исторический URL → 301 → товар 200.
Удалённая страница без замены → 410.
Внутренние ссылки и canonical → новые цели.
```

## Почему

Пользователь приходит с закладки, из рекламы и поиска, минуя главную. Перенос URL требует проверки смысла содержимого, сохранения значимых параметров и статуса ответа.

## Когда применять

При смене движка, структуры адресов, домена или хостинга. Если URL и содержание сохранены, перенос на другой сервер не требует массовых редиректов.

### Требования

- Составьте таблицу `старый URL → цель → класс → ожидаемый статус → canonical`. Включите URL из sitemap, источника, внутренних ссылок, внешних ссылок и наблюдаемого трафика. Сопоставляйте по объекту и смыслу, сохраняя вложенность и действующие адреса категорий, документов и вариантов.
- Для постоянной замены используйте серверный постоянный редирект на подходящую страницу. Учитывайте разницу 301/308 для методов. Не переносите POST и платёжные callback на другой адрес по правилам редиректов страниц без проверки контракта.
- Не отправляйте неизвестные или удалённые URL на главную. Реальный 404/410 выбирается по смыслу. Технические страницы старого шаблона обрабатывайте по явному списку; случайное отсутствие настоящей карточки остаётся дефектом.
- Оставьте значимые параметры, в том числе выбранный вариант, фильтр, пагинацию или параметры заявки по контракту. Перезапишите внутренние ссылки в HTML, структурированных полях, хлебных крошках и связанных карточках. Внешние ссылки сохраняйте, если они по-прежнему нужны.
- У canonical, внутренних переходов и sitemap есть одна согласованная цель. В sitemap помещайте только разрешённые индексируемые URL. Preview, черновики, перенаправления и закрытые записи исключаются.
- Пройдите весь реестр ограниченным темпом. Проверка оценивает первый ответ без перехода, конечную страницу, отсутствие цикла, тип сущности, видимый контент и ссылки.

## Пример применения

У типографии товар и таблица открываются на старом адресе раздела. Историческая подстраница перенаправляется прямо на этот товар. Значимая ссылка на расчёт передаёт параметры тиража в новый адрес по явному контракту.

## Как проверить

- Откройте прямой старый URL карточки, вложенного раздела и файла. Сверьте статус, цепочку и фактическую сущность.
- Полностью обойдите реестр и выдайте список неожиданного 404/410, цепочек, дублей canonical, ошибок и ссылок на старый хост.
- Перейдите из хлебных крошек и из содержимого карточки на мобильном и настольном экране.

## Человек

Утверждает удаление, объединения URL и смысл перенаправлений.

## Агент

Агент строит карту и проверяет статусы, конечные объекты, внутренние ссылки и индексирование.
